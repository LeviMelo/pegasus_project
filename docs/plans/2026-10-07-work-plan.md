# The work plan: units, contracts, done

**Status:** building. The one plan of the work from 2026-10-07 to S7. It turns ARCHITECTURE §12's packages into units of work, each with its place in the architecture, its contract with the rest of the system and a check that says it is done. The package plans (`2026-10-07-fields-from-roles.md`, `2026-10-07-questions-and-methods.md`, `2026-10-06-optimization.md`) hold the designs; this plan holds the order and the definitions of done.

**Why.** Work on 2026-10-06 and 2026-10-07 started from the latest result, not from a plan: a mechanism was built, then the next, each locally reasonable, none integrated, none with a definition of done, and the documents fell behind (`docs/discussion/2026-10-07-survey.md`). The author's diagnosis: the work itself was not modular.

## 1. How work proceeds

- **A unit is the only way work starts.** Its entry below names: the goal, the ARCHITECTURE sections, the modules it changes, what it reads and what it hands on (the contract), what it replaces, and **done when**.
- **One unit in progress at a time.** A background measurement for another unit may run beside it. Work discovered during a unit becomes a new entry here (or a §13.2 row), never an inline detour.
- **Done when is checked, and the check is named in the commit.** Checks are on real data, at the smallest scale that settles them (one field, one year, one chapter); a national run is a reading, made when a unit's purpose is the reading.
- **A unit closes in one commit with its documentation:** the ARCHITECTURE section it changed, §13 rows opened or closed, STATUS's line for the package, this plan's entry marked done.
- **The agent decides** (the author is away and does not architect, 2026-10-07). Decisions are recorded where they are owned (CLAUDE.md §7); the author is asked only before acting outward.

## 2. The target shape: one persistent state, computed once

PegaSUS is one persistent state read many ways (ARCHITECTURE §1.1). Speed comes from computing each object of that state **once**, keyed by its content, and from one orchestrator that knows the objects' dependencies, never from computing less than the full survey. A full reading of every system is the default product.

| object | key (what it reads) | producer | readers |
|---|---|---|---|
| assembled block | the gateway query's arguments, data version, the source of the functions it calls | `monolith.assemble` | fits |
| fit (and its robust refit) | block, model spec, data | `monolith` | noise, surprise, totals |
| noise structure (N1) | fit, field | `surprise` | every method of the field |
| surprise | fit, field, reference | `surprise` | methods |
| spatial basis (spectrum, scales, heat kernels) | the place graph | `multiscale` | every multiscale method, every field |
| spatial structure of a field's surprise | surprise, graph | `surprise.spatial_structure` | excess, step, trend |
| answers | field, question, method, settings | `questions` | merge, ledger |
| merged answers, leads | answers | `questions`, `leads` | stage E |
| stage-E verdicts | lead, the rule version, the corroborating sources | `replication`, `corroborate`, `scans.explain` | report |
| reading | register | `report` | the person |

- **Keys by content.** An object's key hashes its inputs and the source of the code it runs, never the repository's commit or a whole module's bytes.
- **One orchestrator.** `update` computes the objects a plan needs in dependency order, stores each when done (a killed run resumes at the next missing object), and schedules them on the machine: CPU threads, the GPU slot, RAM. It replaces `heavy.py` (now `pegasus-core run`), `data/chain.py` and every `data/queue_*.py`.
- **Nothing is computed inside a reader.** A reading that needs an object asks the state for it; a missing object is computed by the orchestrator as a declared step, never silently (the national fit inside `_expected_total` today).

### Units added 2026-10-08, from the S2–S5 results

What exists, surveyed 2026-10-08 (code and stores):

- **PegaSUS reads links as one link's raw pairs only.** A stored run is a table of pairs, `(l, r, bits, p_match)`, of record identities (file hash and row), and a report (verdict, false-match rate, validations); nothing merged is stored. The pairs are read in four places:
  - `gateway.side_pairs` and `covering_runs`: a side's year through every run that holds it;
  - `gateway.linked_counts`: linked-share fields, read by `monolith`, the dependency map (`dependency.py`) and corroboration's overlap (`corroborate.source_year`);
  - `gateway.cohort_records` with `tools.cohort`: the cohort scan;
  - `gateway.link_sensitivity` and `link_completeness`: S2.3.
- **pegasus_data has the person level; PegaSUS calls none of it.**
  - `linkage.entities.build_entities(period, geography)` merges every stored run of a scope into persons, strongest evidence first, under the constraints one birth per baby, one death per person, and never baby and mother at once. A broken constraint is refused and reported. 2022 nationally: 2.39 M pairs became 2.37 M persons in 42 s, with 78 refusals (pegasus_data evaluation 2026-10-03-entities-from-national-links).
  - `person_pairs(entities, (dataset, role), (dataset, role))` gives the pairs of any two record kinds through persons. In 2022 the routes through deaths added 12.6 % to the admission–baby pairs, and 97.6 % of triangles agreed.
  - `linkage.uncertainty.draws` (`pegasus_data.link_draws`) and `combine` (Rubin): link draws. `tools.cohort` draws its own (`rng.random(len(p)) < p`), a second mechanism.
  - `linkage.timeline`: one pregnancy's events.
- **Stored runs in PegaSUS's data root** (`lake/links/`):
  - infant deaths → SINASC: 2010–2023;
  - SIH deaths → SIM: 2014–2023 (2010–2013 failed before pegasus_data 9160d53 and wait for `pegasus-core links`);
  - dengue deaths → SIM: 2012–2023, of which 2015, 2021 and 2023 are stored as not viable;
  - births → SIH delivery: 2014–2023;
  - women's deaths → SINASC mothers: deterministic, 2015–2022.
  - None of the newborn-admission link (`sih_neonatal_admissions_to_sinasc`) or of the CIHA links. Entities over a scope need every link of the scope stored.

# Tools over MCP: a first build, exercised live; paused for the author's plan

**What.** `src/pegasus_core/mcp_server.py` serves the Python API over MCP. It uses the official SDK, over stdio, as the optional extra `mcp`.
- **Reading tools:** `list_blocks`, `list_fields`, `get_expectation`, `search_leads`, `explain_lead`, `place_story`, `gate_status`, `ledger_status`.
- **The one write, `confirm_claim`.** It spends the confirmation reserve only if all three hold:
  - the server was started with `--allow-confirm`;
  - the call says `spend=true`;
  - the call names a `caller`.
- **Resources:** the ARCHITECTURE sections and the evaluation entries.

ADR-0008 records the design.

**Status: paused (author, 2026-10-05).** How the tools are used and integrated is to be planned with the author before anything relies on them. The build is committed so that the development history stays coherent; it is not wired into any user configuration.

**Regime.** 2026-10-05, code 52d895d, the real `pegasus_home`. Run by `scripts/mcp_demo.py` (real client, stdio, through `scripts/heavy.py`). Logs: `data/logs/mcp_demo_read.out`, `mcp_demo_spend.json`.

**Observed:**
- **The server lists its nine tools and two resource families.**
- **`list_blocks` (0.6 s)** returns the fitted SIM blocks: 41 fits, including chapters I–XX for 2010–2023 on contiguity. It carries provenance: data version, pegasus_data commit, code version, population source.
- **`gate_status` (0.2 s)** returns the harness's false-lead worlds per lens.
- **`search_leads` (2.6 s)** returned 419 outbreak leads classed as signal among the 7,496 in the register. The top one is A92 (chikungunya) in Fortaleza (230440) in 2017.
- **The write path** was exercised on a copy of the ledger (`mcp_demo_spend.json`).

**Not done:**
- latency on a cold block (first reads take minutes; `MCP_TOOL_TIMEOUT` is documented);
- any use by a real agent loop: that is part of the planning with the author.
